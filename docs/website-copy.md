# Updating the public SMEme website

This repository publishes the live public site at `https://smeme.ai`. The
hosted application lives at `https://app.smeme.ai`; copy-only changes belong in
this repository and do not require a Cloud image, Core image pin, Clerk, or
Stripe change.

## Before editing

- Use the approved wording in
  [`smeme_v2/docs/product/messaging.md`](https://github.com/AristaLabs/smeme-cloud/blob/main/docs/product/messaging.md).
  This runbook describes implementation and publishing; it does not replace
  the messaging decisions.
- Use the
  [GEO execution plan](https://github.com/AristaLabs/smeme-cloud/blob/main/docs/business/geo-execution-plan.md)
  for discovery priorities and page requirements.
- Keep `/docs/delete-account` on `app.smeme.ai`. It is an authenticated app
  page, not a generated static page. `/docs/plans` is the hosted plans page in
  this repository.
- `aristalabs.ai` is maintained in its own repository.

## Change a page

Edit the Jinja templates under `src/templates/`. Landing, documentation, and
legal templates map to the `LANDING`, `DOCS`, and `LEGAL` route maps in
[`build.py`](../build.py).

When adding a public page, update all of these together:

1. Add the route and template to the appropriate route map.
2. Add the same route to `PUBLIC_ROUTES`, including its title and description.
3. Add a canonical URL on `https://smeme.ai` to the template. Landing and docs
   pages use their existing SEO partials; legal pages inherit the canonical
   link from `legal/_layout.html`.
4. Add any required internal navigation links and verify that app-owned links
   use the app host.

`PUBLIC_ROUTES` drives `sitemap.xml`, `llms.txt`, and `llms-full.txt`. Do not
edit those generated files directly.

`build.py` rewrites account, dashboard, billing, API, MCP, and delete-account
links to `https://app.smeme.ai`. The waitlist is a normal form post to
`https://app.smeme.ai/teams-waitlist`; keep it out of the static site's
runtime. Do not leave relative `/auth`, `/decision-trees`, `/billing`,
`/api`, `/well-known`, `/docs/delete-account`, or `/teams-waitlist` targets in
generated app-owned attributes.

## Local verification

Generated output is in `public/` and is gitignored. Build and serve it locally:

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
python3 build.py
python3 -m unittest discover -s tests -p 'test_*.py'
python3 -m http.server 8000 --directory public
```

Open the changed route and verify its canonical URL, app links, and page
content. The static tests validate generated files from a clean output
directory. They are not a substitute for checking the deployed hosts.

## Publish

Submit a pull request and merge it to `main`. The Render Static Site then
builds from `main` with:

- Build command: `pip install -r requirements.txt && python build.py`
- Publish directory: `public`
- Deploy source: automatic deploy from `main`

Before merging, verify the Render settings still match those values. Do not
make DNS, Clerk, Stripe, `BASE_URL`, or `PUBLIC_SITE_URL` changes for a
copy-only update.

After deployment, manually check:

1. The changed page on `https://smeme.ai`.
2. `https://smeme.ai/sitemap.xml`, `llms.txt`, and `llms-full.txt`.
3. A representative account, dashboard, API, MCP, and delete-account link.
4. The waitlist form target, without submitting an unintended entry.

Record any failure in the site PR and fix it before treating the copy update
as complete.

## Site build lessons

- A public route must be registered in both its route map and `PUBLIC_ROUTES`.
- `PUBLIC_ROUTES` also controls the sitemap and both LLM crawler files.
- `public/` is generated output; edit `src/templates/` or `build.py`, then
  rebuild.
- `build.py` rewrites app-owned links to `app.smeme.ai`; the waitlist remains
  a normal form post to the Cloud app.
- `/docs/delete-account` is owned by the authenticated app and must not be
  generated by this repository.
- The Cloud repository retains fallback landing templates and the waitlist
  endpoint, but production public pages are served by this static site.
- DNS, Clerk, Stripe, `BASE_URL`, and `PUBLIC_SITE_URL` cutover behavior is
  recorded under "Hosted Static-Site Split" in the Cloud
  [lessons learned](https://github.com/AristaLabs/smeme-cloud/blob/main/docs/LESSONS_LEARNED.md#hosted-static-site-split).
